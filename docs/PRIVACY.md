# Privacy and security notes

A photo is sent to the backend only when the user chooses a label photo with saved AI permission enabled. Permission is optional during first-visit onboarding, stored under a provider-versioned localStorage key, and can be withdrawn in Settings. Withdrawal blocks future scans but cannot recall earlier provider requests. Clearing browser storage triggers onboarding again. This is browser-local setup, not a personal account or cross-device profile. The backend validates file contents, limits size/dimensions, removes EXIF metadata and sends a normalized JPEG to Google's Gemini API. HEIC/HEIF photos are decoded on the server; unsupported browser previews do not prevent conversion. Do not photograph faces, prescriptions, receipts with payment details, or other unnecessary personal data.

The application does not persist photo files or results in a database. Uploads are handled in process memory. Python objects are not cryptographically erased; hosting infrastructure and the external provider may have separate telemetry and retention. Provider data use depends on the paid/free service and account configuration. Review provider terms before launch; this project does not claim zero external retention.

Only the text result is saved in browser localStorage when the user taps Save scan. Up to 20 scans are retained on that browser profile until deleted. Dietary preference is also stored locally. Browser profiles may sync or be shared depending on device settings; FoodLens does not provide encrypted or account-isolated saved history.

Shopping search requests contain the item name, saved dietary preference and either rounded browser coordinates (about 100-metre precision) or a Dutch city/postcode chosen by the user. FoodLens does not save those values. Coordinates are sent to OpenStreetMap's Overpass service to identify nearby supermarket chains; typed locations are first resolved by OpenStreetMap Nominatim. English item text may be sent to Gemini for Dutch translation. Current catalogue prices are retrieved from Checkjebon.nl and the EUR/INR reference rate from the European Central Bank. Those services and the hosting provider may keep their own network logs under their policies. Location access is requested only after the user starts a comparison or taps the location control.

The app uses a short-lived signed session cookie for private-beta access and a CSRF cookie. Client request IPs are HMACed for rate-limit keys; no raw photo or model response is deliberately logged. Hosting access logs may still contain client network data. Do not enable request-body logging in a proxy or APM tool.

No third-party frontend libraries, tracking scripts or external fonts are loaded. Model strings are rendered with textContent rather than HTML. The label-reading AI receives no browsing tools, and grocery prices never come from model output. API credentials remain in environment variables and are sent to the provider in a header, never a URL query string.

Production must use HTTPS, an exact host allowlist, trusted origins, a strong secret, individual authentication and Redis-backed shared quotas. Set an ingress body-size limit and review external data-source terms before a broader launch.
